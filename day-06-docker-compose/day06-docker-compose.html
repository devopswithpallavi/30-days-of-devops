What is Docker Compose?

Docker Compose is a tool for defining and running multi-container Docker applications. Instead of running multiple docker run commands manually, you define everything in a single docker-compose.yml file and start it all with one command.

❌ Without Compose
Run network → Run MySQL → Run Flask → Remember all flags, env vars, ports every time. Very error-prone.
✅ With Compose
One docker compose up command. Everything defined in one file. Easy to share, version control, and reproduce.
💡 Docker Compose is perfect for local development and testing multi-container apps. It automatically handles networking between containers!

Install check

 Terminal
# Check if Docker Compose is installed
$ docker compose version
# Docker Compose v2.x.x
02
docker-compose.yml Structure

The docker-compose.yml file is written in YAML format. It defines all the services (containers), networks, and volumes your application needs. Indentation matters in YAML — always use spaces, never tabs.

 Basic Structure
version: '3.8'                # Compose file version
services:                     # Define containers here
  service-name:
    image: image-name
    ports:
      - "host:container"
    environment:
      - KEY=value
networks:                     # Define networks here
volumes:                      # Define volumes here
KeyWhat it does
versionCompose file format version (use 3.8)
servicesDefine all containers/applications
networksDefine custom networks
volumesDefine persistent storage
03
Services

Each service represents one container. You can define the image, ports, environment variables, volumes, networks, and more for each service.

image
Docker image to use — e.g. mysql, nginx, python:3.9-slim
build
Build image from a Dockerfile instead of pulling — use build: . for current directory
ports
Map host port to container port — "5000:5000" means host:container
environment
Set environment variables inside the container — DB credentials, config values, etc.
volumes
Mount volumes for persistent data — data survives even after container restart
depends_on
Start this service only after another service is running — e.g. Flask after MySQL
networks
Connect this service to specific networks — containers on same network can talk
restart
Auto-restart policy — always, on-failure, unless-stopped
04
Networks in Compose

Docker Compose automatically creates a default network for your app. All services in the same Compose file can communicate using their service name as the hostname — no manual network creation needed!

💡 In Compose, services talk using service name as hostname. Flask can reach MySQL at mysql because that's the service name — Docker DNS handles the rest!
✅ Default Network
Compose auto-creates a network. All services connected automatically. No extra config needed.
🔧 Custom Network
Define your own network under networks: for better control and naming.

Custom network in Compose

 docker-compose.yml
services:
  flask-app:
    networks:
      - two-tier
  mysql:
    networks:
      - two-tier
networks:
  two-tier:
    driver: bridge
05
Volumes — Persistent Data

By default, container data is lost when the container stops. Volumes solve this by storing data on the host machine — so your database data survives container restarts!

❌ Without Volume
Container stops → all data gone. MySQL database wiped. Start from scratch every time.
✅ With Volume
Data stored on host. Container restarts → data still there. Persistent storage.
 Volume in docker-compose.yml
services:
  mysql:
    image: mysql
    volumes:
      - mysql-data:/var/lib/mysql # persist DB data
volumes:
  mysql-data: # named volume definition
📌 /var/lib/mysql is where MySQL stores all its data inside the container. Mounting a volume here keeps your data safe!
06
Environment Variables

Environment variables pass configuration to containers — like database credentials, hostnames, and API keys. In Compose you can define them directly or use a .env file for better security.

Method 1 — Inline in compose file

 Inline environment
services:
  mysql:
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: devops
      MYSQL_USER: admin

Method 2 — Using .env file (recommended)

 .env file
MYSQL_ROOT_PASSWORD=root
MYSQL_DATABASE=devops
MYSQL_USER=admin
 Reference in compose file
services:
  mysql:
    env_file:
      - .env
⚠️ Always add .env to your .gitignore file — never push passwords to GitHub!
07
depends_on

depends_on tells Docker Compose the startup order of services. For example, Flask app should start only after MySQL is running — otherwise Flask will crash trying to connect to a database that doesn't exist yet.

⚠️ depends_on only waits for the container to start — not for the service inside to be ready. MySQL might still be initializing when Flask tries to connect!
 depends_on example
services:
  flask-app:
    build: .
    depends_on:
      - mysql # start mysql first, then flask
  mysql:
    image: mysql
08
Two-Tier App with Compose

This is the same Flask + MySQL Two-Tier App from Day 5 — but now using Docker Compose. Instead of 6+ manual commands, everything runs with one single command!

 docker-compose.yml — Complete file
version: '3.8'
services:
  mysql:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: devops
    volumes:
      - mysql-data:/var/lib/mysql
    networks:
      - two-tier
    restart: always
  flask-app:
    build: .
    ports:
      - "5000:5000"
    environment:
      MYSQL_HOST: mysql # service name = hostname
      MYSQL_USER: root
      MYSQL_PASSWORD: root
      MYSQL_DB: devops
    depends_on:
      - mysql
    networks:
      - two-tier
    restart: always
networks:
  two-tier:
    driver: bridge
volumes:
  mysql-data:

Run everything with ONE command!

 Start & Stop
$ docker compose up -d      # start everything in background
$ docker compose down       # stop & remove containers
$ docker compose down -v    # stop & remove volumes too
$ docker compose logs -f   # follow all logs
$ docker compose ps         # see status of all services
$ docker compose build      # rebuild images
$ docker compose restart    # restart all services
✅ docker compose up -d replaces: network create + mysql run + flask run — all in ONE command! That's the power of Compose.
